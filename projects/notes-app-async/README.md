# 📦 notes-app 상태 외부화 + 비동기 처리

> ElastiCache로 세션 외부화, SQS/SNS로 비동기 분리, KEDA로 자동 스케일

## 개요

| 항목 | 내용 |
|------|------|
| 기간 | 2026.08 |
| 목표 | 무상태 아키텍처 + 비동기 처리 + 이벤트 기반 오토스케일 |
| 환경 | AWS EKS + ElastiCache + SQS + SNS + KEDA |

## 아키텍처

```
사용자 → API (무상태)
           ├── 세션: ElastiCache
           ├── 느린 작업: SQS에 넣고 즉시 응답
           │                 ↓
           │            워커 Pod (KEDA: 0~10개 자동)
           │                 ↓
           │            SNS 팬아웃
           │              ├── 알림 큐
           │              └── 감사 큐
           └── 비밀: ESO (Day 5)
```

## 핵심 검증

```
큐 비었을 때:   Pod 0개 (비용 0!)
메시지 15개:    Pod 자동 생성 (KEDA 스케일 업!)
처리 완료 후:   Pod 다시 0개로 축소
```

## 배운 점

**상태를 밖으로 빼야 진짜 클라우드 네이티브다.** Pod에 상태가 있으면 스케일링도, 롤링 배포도 제대로 안 된다.

**KEDA는 외부 메트릭으로 0까지 축소한다.** HPA는 CPU/메모리 + 최소 1개지만, KEDA는 큐 길이 기반 + 0개까지. 이게 비용 최적화의 핵심.
